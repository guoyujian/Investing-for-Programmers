### 本章最重要的概念

#### 1. 金融数据不是一种东西，而是至少三种不同问题

这一章最先要你分清：

- 基本面数据（fundamental data）：财务报表、比率、公司披露
- 技术数据（technical data）：价格、成交量、收益率、波动
- 非财务数据（nonfinancial data）：新闻、情绪、文本、管理层表达、舆情等

它们不只是格式不同，而是在回答不同问题。你后面如果抓数据却不先分类型，分析会很容易混线。

#### 2. 平台适合看，API 适合接，scraping 风险最高

作者在这一章里隐含地给了一个很重要的工程判断：

- 平台 / 网站适合人类浏览和筛选
- API 更适合程序稳定接入
- 直接 scraping 虽然能用，但维护风险最高

这和程序员做系统时的习惯很像。能走正式接口，就尽量别把页面结构当长期依赖。

#### 3. 个人研究早期更适合 notebook，而不是先造完整应用

这一章会提醒你：做个人投资研究时，不要过早 app 化。`Jupyter`、`Databricks` 这类 notebook 环境更适合先探索数据、试假设、看结果。

这不是说应用不重要，而是说研究阶段最重要的是：

- 交互快
- 试错快
- 能快速看见数据和中间结果

#### 4. `yfinance` 是很好的上手工具，但不是无条件可靠的数据底座

这是本章最值得记住的工程边界之一：

- `yfinance` 很适合入门、原型、个人研究
- 但它底层依赖 Yahoo 的接口和 scraping 逻辑
- 一旦上游改动、反爬、字段变化，你的流程就可能失效

所以本章真正想教的不是“只会 `yfinance`”，而是“先用它起步，同时保留替换数据源的意识”。

#### 5. 换数据源的成本，本质上是研究系统设计问题

后半章介绍 `Finviz`、`EODHD`、`Alpha Vantage`、`OpenBB`，重点不只是让你知道名字，而是让你理解：

- 不同提供方覆盖的市场不同
- 免费版和付费版的能力边界不同
- 如果接口风格相近，后面切换成本就更低

这对程序员特别重要，因为你后面做监控、打分、组合工具时，数据提供方迟早会成为架构约束的一部分。

## 分节预习笔记

### 3.1 Financial data

#### 这一节最该抓住的主线

- 金融数据质量通常比很多其他领域更高，因为报表和披露有审计和标准
- 但“质量较高”不等于“拿来就能直接分析”
- 数据至少要分成基本面、技术、非财务三类来看

#### 三类数据分别在补什么视角

- 基本面数据：告诉你公司经营和财务状态怎样，适合回答“这家公司底子如何”
- 技术数据：告诉你价格、波动、走势怎样，适合回答“市场过去怎么给它定价”
- 非财务数据：告诉你新闻、情绪、文本、管理层表达等语境，适合回答“数字之外发生了什么”

#### 对当前阶段最重要的结论

- 你后面抓数据前，先别问“这个库好不好”，先问“我要的是哪类数据”

### 3.2 Financial analysis platforms

#### 这一节最该抓住的主线

- 平台的价值不只是展示数据，还能帮你缩小候选范围
- `stock screener` 的核心用途，是先筛掉不符合条件的公司，再进入深分析
- 真正要进代码工作流时，最好优先考虑 API，而不是长期依赖网页结构

#### 对程序员最有用的提醒

- 平台适合探索和筛选
- API 适合稳定接入
- scraping 可以救急，但别轻易把它当长期底座

### 3.3 Data science notebooks

#### 这一节最该抓住的主线

- notebook 是研究环境，不只是教学环境
- 它的优势是单元格式执行、结果即时可见、非常适合探索式分析
- 对个人投资研究来说，它通常比一上来写完整应用更高效

#### 对当前阶段最重要的结论

- 先在 notebook 里把问题跑通、把数据看懂、把图表画出来，再考虑要不要做成工具

### 3.4 yfinance

#### 这一节最该抓住的主线

- `yfinance` 是本书的数据入门接口
- 它能让你很快拿到公司报表、历史价格和部分指标
- 但本章真正重要的是：学会通过它理解“一个金融研究脚本该怎么组织”

#### 3.4.1 Fundamental analysis

- 可以直接访问利润表、资产负债表、现金流量表及其季度版本
- 也能从对象属性里提取常见比率和公司信息
- 这意味着 Chapter 2 里的很多概念，现在都能从静态术语变成实际 DataFrame 或字段

#### 3.4.2 Technical analysis

- 可以拉取历史价格时间序列，观察高低点、涨跌、收益率和波动
- 作者引入了简单收益率、对数收益率、均值、标准差、方差这些最基础统计量
- 重点不是技术分析神秘，而是先学会把价格序列变成可比较、可统计的对象

#### 3.4.3 Limitations of yfinance

- `yfinance` 依赖 Yahoo 的接口和 scraping 逻辑
- Yahoo 不负责维护这个开源库，上游一改，结果就可能失效
- 某些数据字段在特定时期可能缺失或不稳定
- 网站如果加强反爬、增加验证码、调整页面结构或改接口策略，抓取流程就可能中断
- 所以它很适合学习和原型，但你要保留替代方案意识

### 3.5 Commercial libraries

#### 这一节最该抓住的主线

- 商业库不只是“花钱买更快”，而是在买更稳定、更广覆盖或更明确的服务边界
- 对个人投资者来说，免费版或 freemium 版也可能已经够做部分研究
- 真正关键的是知道不同供应商各自强在哪里、限制在哪里

#### 3.5.1 Finviz

- 强项是美国市场和强大的 screener
- 对只看美股的用户有吸引力
- 但国际市场覆盖有限

#### 3.5.2 EODHD

- 更强调广泛交易所覆盖和相对熟悉的接口风格
- 如果以后从 `yfinance` 迁移，代码改造成本可能更低

#### 3.5.3 Alpha Vantage

- 提供 API 方式的数据访问，免费版和付费版能力不同
- 除价格数据外，还能拿到一些额外数据，例如新闻情绪
- 但部分更完整数据能力需要高级订阅

#### 3.5.4 OpenBB

- 最大亮点是不只做股票
- 还覆盖外汇、固定收益、加密资产等多类市场
- 对想做多资产研究的程序员尤其有吸引力

### 3.6 Other libraries

- 作者没有要求你把所有库都学一遍
- 这一节更像是在提醒你：金融数据生态很大，选型错误会带来重写成本
- 比起“找最全的库”，更重要的是先形成稳定的最小研究工作流

## 本章收束

学完这一章后，你最应该留下的不是某个 API 的细枝末节，而是下面这几个稳定结论：

1. 金融数据先分类型，再谈抓取方式
2. 研究早期优先 notebook，先别急着产品化
3. `yfinance` 很适合起步，但不要把它误当成无条件可靠底座
4. 数据提供方的覆盖范围、稳定性和替换成本，都会影响你的研究系统设计
5. 从这一章开始，你已经在搭自己的最小投资研究管线了

## 问答沉淀

### Q：这一章是本书的重点吗？

A：是，Chapter 3 属于全书前半段的重要地基章。它的重要性不是因为它教了某个具体库，而是因为它把前一章学到的财务语言，正式接到“数据从哪里来、怎么抓、怎么放进研究流程”这条主线上。

更准确地说，这一章的重点是建立数据工作流意识：

- 先分清 `fundamental / technical / nonfinancial data`
- 再理解 `platform / API / notebook / scraping` 的边界
- 然后用 `yfinance` 跑通最小流程
- 同时知道它的限制和替代方案

如果把这章跳过去，后面 Chapter 4-6 很容易变成“知道想研究什么，但不会稳定拿数据”。

但如果你问“是不是要把每个库的细节都背下来”，答案是否定的。真正要精读的是 `3.1 + 3.3 + 3.4 + 3.4.3 + 3.5` 这条主线，而不是把它读成工具说明书。

### Q：很多网站不是会做反爬吗？这不就很容易导致我们拿不到数据吗？

A：对，这正是 `scraping` 的核心风险之一，而且可以说是这一章想提醒你的重点。网页抓取不是“完全不能用”，而是“很难保证长期稳定可用”。

网站一旦出现下面这些变化，原来能跑的抓取脚本就可能失效：

- 改 HTML 结构
- 增加登录校验
- 限制请求频率
- 加验证码
- 封 IP
- 改字段命名

所以真正的问题不是“今天能不能抓到”，而是“下个月、下个季度还能不能稳定抓到”。

这也是作者为什么更推荐把 scraping 看成过渡方案，把正式 `API` 看成更稳的长期方案。对个人学习和原型来说，像 `yfinance` 这样的工具依然很好用；但如果你要把它当成长期研究系统的底座，就必须提前接受一个事实：上游一变，你就得跟着修，甚至换源。
